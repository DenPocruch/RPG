# Конструктор дома — концепт (режим планировки в стиле Hay Day)

Дата: 2026-10-03. Статус: концепт согласован, код не начат.
Связанные места проекта: `SampleScene` (`Interior`, `InteriorFloor`, `InteriorWalls`, `HouseDoor`, `InteriorSpawn`), `Assets/Art/Tileset/Tileset House.png`, тайлы `Assets/Art/Tileset Grass Spring/Home/`, мебель `Assets/Prefab/Interior/`, магазин `ShopInteraction.EnsureFarmStock`, сейвы `SaveManager` (версия 2).

## 1. Идея
Игрок покупает многоразовую карточку «Чертёж дома», нажимает её в инвентаре и попадает в режим планировки. Сбоку панель-каталог как в Hay Day: Полы | Стены | Мебель | Расширение | Магазин. Тап по каталогу + тап/драг по сцене = поставить. Всё покупается прямо в панели, старый пол/стена возвращается в тот же склад.

## 2. Зафиксированные решения
- Склад дома **отдельный** (`house_stock`), не рюкзак. Одинаковые предметы **стакаются без лимита** (счётчик `int`).
- Замена пола/стены: старый тайл `+1` в склад, новый `-1`. Нет в складе — кнопка «Купить» в панели.
- Расширение: **1-й тайл = 50 дерева + 500g** (база голды на подтверждение владельца). Дальше каждые 5 покупок `+25 дерева и +250 голды`: тайлы 1–5 = 50/500, 6–10 = 75/750, 11–15 = 100/1000 и т.д.
- Чертёж **многоразовый**, мир в планировке **тикает** (паузы нет).
- Панель строит владелец **вручную** в `SampleScene/Canvas`. Код только подключается через биндер (`HouseEditBinder`, перетаскивание в инспекторе, как `ShopUI`/конструктор). Кодового UI по умолчанию не городить.
- Камера: игрок стоит (джойстик/атака скрыты), пан одним пальцем **по пустому месту**, щипок-зум 0.7x–1.5x, зона = rect дома + 3 тайла, не вылезать за `CameraBoundsZone` интерьера. Выход — камера назад на игрока.
- Перенос декора на сцене: **лонг-пресс 0.5 сек** (вибрация + полупрозрачность), драг, отпустил — встало. Дотянул до панели склада — упало в склад.
- Принято (03.10): а) подсвечивать клетку-источник пока несёшь мебель; б) невалидный дроп = возврат на старое место, а не в склад и не на пол.
- Принято (03.10): ковры — слой декора поверх пола (пол под ними сохраняется, коллайдера нет, как свечи `noCollider`).
- Отклонено (03.10): требование «2 клетки для громоздкой мебели» — не нужно, т.к. мебель это префабы с физическими коллайдерами, а стены/пол это тайлы. Валидация простая: футпринт префаба не должен пересекать тайлы стен (`wallTilemap.HasTile`) и чужые коллайдеры; проверка по физике, а не по счёту клеток.
- Отклонено (03.10): серые иконки «нельзя сюда» в каталоге. Вместо этого — подсветка контура зоны при драге (см. раздел 6).
- Мебель ставится **только внутри дома**: напольная — только на тайл пола, настенная — только на тайл стены. За стены/наружу в планировке ставить нельзя.

## 3. Откуда взята логика
- Stardew Valley: обои красят всю комнату, предмет одноразовый, дом качается у плотника за дерево+голду поэтапно. Их грабли — сломанная сетка поклейки после расширения, поэтому у нас слои пола и стен раздельные.
- Hay Day: отдельный режим, каталог сбоку, старый декор возвращается в тот же склад, Готово/Отмена с откатом.
- Sims/Terraria: стены стыкуются кодом по битмаске соседей (прямая/угол/Т-стык), а не руками.
- Unity: `RuleTile/AutoTile` (наборы 16/47) — для рантайма берём свой кодовый автотайлер, а не пачку ассетов.

## 4. Расширение по тайлам (дом НЕ прямоугольный — уточнено 03.10)
Сейчас 60 тайлов пола (правая комната; замерено по сцене 04.10, раньше глазомерно было «30»). Старт — базовый дом, дальше игрок расширяет сам. Поэтому расширение — не «полоса на сторону», а **+1 тайл, смежный с существующим полом** (игрок тапает клетку-призрак рядом с домом). Новый тайл получает пол текущего стиля; стены пересчитывает `HouseAutotiler` по 8 соседям вокруг всего контура (внешний край — стена, стык со старым полом — проход). Лимит — **100 тайлов пола** (подтверждено 03.10: 30 сейчас + 70 покупок), кап по счётчику, не по габаритам. Цена-лесенка та же: 50 дерева + 500g, каждые 5 купленных тайлов +25/+250. Проверки: клетка-призрак внутри зоны камеры, не на мебели/двери/`InteriorSpawn`.
- Дверь снизу (подтверждено 03.10): расширение **только вбок и вверх**, ниже уровня двери строить нельзя (клетки с `y < y_двери` запрещены, ghost там не появляется). Дверь фиксирована, автоперенос не нужен.

## 5. Мебель: поверхность установки + база пол/стена (03.10)
Все префабы = `SpriteRenderer + BoxCollider2D + YSort` (скрипта-логики нет, свечи без коллайдера). Всего ~1180 префабов в 21 папке `Assets/Prefab/Interior/`. Разметка — таблицей, а не руками по каждому:
- `FurnitureMountTable` (SO в `Resources/House/`): `имя префаба → mount (Floor/Wall/Both)`. Билдер `Tools → House → Build Furniture Mount Table` сканирует префабы и **дописывает только недостающие** (ручные правки не трёт, как `FishBuilder`): папки `Part1/Part2/Part9/Part10/Part11` → Wall по дефолту (настенный декор: картины, зеркала, часы, полки, лампы), все остальные → Floor. Исключения владелец правит вручную в таблице.
- Рантайм-фолбэк без таблицы: имя папки начинается с `Part` → Wall, иначе Floor.
- Напольная: футпринт префаба (его `BoxCollider2D`) не пересекает тайлы стен (`wallTilemap.HasTile`) и чужие коллайдеры + стоит на тайле пола. Свечи/мелочь без коллайдера — точка привязки на полу.
- Настенная: snap к стене + движение вдоль стены, кламп — весь спрайт целиком на тайлах стены, свисание на пол/за карту запрещено.
- Ковры — слой декора поверх пола (пол сохраняется, коллайдера нет).
- При замене стены под настенным декором декор автоматически падает в склад с сообщением.
- Вкладки каталога фильтруют по `mount`, на превью — иконка «на пол / на стену».
- Стартовый разбор по папкам (шт): Wall-дефолт: Part1 91, Part10 62, Part11 48, Part2 33, Part9 28 (итого 262). Floor-дефолт: Closet 204, Chairs 117, Tables 116, Beds 90, Sofa 76, School 66, Cats 64, Xmas 64, Dressers 60, Fireplace 30, Blacksmith 25, Candles 28, Hospital 17, Temple 10, Others 9, Basketball 3 (остальное). Xmas/Cats/School — ОТЛОЖЕНО (03.10): разберёмся при добавлении, дефолт Floor.
- Тестовый каталог v1 (принято 03.10): не все 1181, а ~8–10 предметов чисто для проверки механики (ориентир: кровать, стол, стул, картина, часы, свеча + по 2 стиля пола и стен). Workflow: код даёт базу — ассет `HouseCatalog` (список `префаб → цена`, `mount` тянется из таблицы; префабы как ассет-ссылки), владелец вручную перетаскивает туда нужные префабы в инспекторе.

## 6. Жесты и конфликты (Android)
Тап = действие; сдвиг >10px или hold ≥0.5с = drag; два пальца = только зум. Касание, начавшееся на UI панели, камеру не двигает (`EventSystem.IsPointerOverGameObject`). Порог драг/тап как в `ItemDragHandler` (10px).

## 6.1. Подсветка контура зоны при драге (принято 03.10 вместо серого каталога)
- Тянешь пол из панели: подсвечивается **общий контур всех плит пола** (одна рамка по периметру `rect`, не каждая плитка). Игрок видит, куда можно класть.
- Тянешь стену/обои: подсвечивается **контур стен** (полоса по периметру).
- Тянешь мебель: подсвечивается свободная площадь пола (валидные клетки приглушённо, контур ярче); стены красным не красим — мебель туда просто не встанет с сообщением.
- Реализация: один overlay-объект `HouseEditZonePreview` (сортировка между полом и ghost, как `ScarecrowZonePreview`), переключается по типу драга. Дешево для телефона: одна рамка вместо сотен подсветок.
- Дроп мимо контура = возврат предмета/кисти, лёгкая тряска + сообщение в лог.
- Отклонено (03.10): режим «кисть-тап» (тап по иконке = кисть, дальше тапы красят). Оставлен только драг из панели с превью. Вариант записан, можно вернуть позже.
- Принято (03.10): настенная мебель магнитится к стене (snap) и двигается вдоль неё вверх/вниз, но целиком: выход за край стены (часть на полу, часть за картой) запрещён — весь спрайт должен лежать на тайлах стены.
- Принято (03.10): счётчик остатка — в слотах инвентаря планировки (иконка + цифра, как в обычном инвентаре), дублировать на контур не надо.
- Принято (03.10): бросок мебели в склад — в любое место панели, точное попадание в слот не требуется. Панель сама находит свободный слот или стакается к таким же (поиск по `id`, стаки без лимита).
